# АвтоПрайс (APrice) — скелет проекта + APrice-Builder

Windows-приложение для оценки рыночной стоимости автомобиля по объявлениям
с пяти российских площадок. Комплекс состоит из трёх компонентов:

| Компонент | Назначение | Статус |
|---|---|---|
| **APrice-Builder** | Формирователь справочной базы (каталог марки → модели → поколения → КПП/топливо/объёмы/мощности) | ✅ реализован (задачи №1–2, включая доработки по код-ревью) |
| **APrice-Server** | Фоновый сборщик объявлений (трей, IPC, парсеры) | ✅ реализован (задача №3) |
| **APrice-Client** | GUI оценки (статистика, история, графики, экспорт) | ✅ реализован (задача №4) |

**Стек:** Разработка и сборка — Python 3.11.x или 3.12.x (НЕ 3.15), PyQt6, Playwright (Chromium), SQLite, pandas/numpy, PyQt6.QtNetwork (IPC на QTcpServer).
**Целевая ОС:** Windows 10/11 x64 (разработка возможна на Linux).

## Отчёт об исследовании источников каталога (п. 4.1 ТЗ)

Проверено 3 ноября 2026 г. (Linux-среда разработки; запросы — прямой HTTPS без прокси).

### 1. Официальный API каталога auto.ru

**Вывод: публичного неавторизованного API каталога не обнаружено.**

* `https://api.auto.ru/...` — хост **не резолвится** (NXDOMAIN);
* `https://auto.ru/cars/all/` (страница каталога) с «голым» curl даже с
  реалистичным User-Agent отвечает **302 → `https://auto.ru/showcaptcha?cc=1&...`**,
  то есть антибот Yandex сразу требует CAPTCHA;
* `https://auto.ru/-/ajax/desktop/listing/` (AJAX выдачи) — тоже **302 на captcha**.

Страницы auto.ru — SPA (Next.js): данные каталога встраиваются в JSON-state
страницы (`__NEXT_DATA__` / инициализационные объекты), но получить их можно
только из «прогретого» браузерного контекста с cookie Yandex (Set-Cookie
`yandexuid` и др.). Это и реализовано как **HTML-фолбэк через Playwright**
(P-01..P-03): stealth-инъекции (`navigator.webdriver`, `plugins`, `languages`),
UA Chrome 124 Win10 + согласованные `sec-ch-ua*`, `ru-RU`, `Europe/Moscow`,
viewport 1920×1080, abort ресурсов `image/media/font/stylesheet`. При редиректе
на `showcaptcha` парсинг прекращается с понятным сообщением в GUI (P-08) —
ручное прохождения CAPTCHA в Builder не предусмотрено ТЗ.

### 2. Альтернативный источник `api.cars-base.ru` — **выбран основным**

Эндпоинты отдают **чистый JSON без браузера**; требуется параметр `token`,
и сервис сам публикует тестовый ключ (`?token=test` — указано в теле ответа 401).
Токен вынесен в `settings.json` (`builder.cars_base_token`) — при переходе на
постоянный ключ меняется только конфиг, не код (задача №2, п. 6).

| Эндпоинт | Ответ |
|---|---|
| `GET /full?token=test` | `{data: [марки], meta}` — 428 марок; марка: `id, name, cyrillic_name, numeric_id, year_from/to, popular, country, models[]`; модель: `id, mark_id, name, year_from/to, class` |
| `GET /generations?token=test` | Все поколения одним запросом: `id, model_id, mark_id, name («III», …), year_from, year_to` |
| `GET /configurations?token=test` | Кузовные конфигурации: `generation_id, body_type, doors_count` |
| `GET /modifications?model_id=BMW_X5&token=test` | Модификации: `generation_id, name ("35i 3.0 AT (306 л.с.) 4WD"), group_name, offers_price_from/to` |

Пример:

```bash
curl "https://api.cars-base.ru/modifications?model_id=BMW_X5&token=test"
# {"data":[{"id":"10382711_...","generation_id":"10382710","model_id":"BMW_X5",
#   "name":"35i 3.0 AT (306 л.с.) 4WD", ...}, ...]}
```

Данные cars-base.ru — это каталог auto.ru (id моделей совпадают со slug'ами
auto.ru, напр. `BMW_X5` ↔ `auto.ru/cars/bmw/x5/`), поэтому источник
соответствует предметной области ТЗ. Объём KПП/топлива/объёма/мощности
извлекается регулярным разбором имён модификаций (`AT→АКПП`, `MT→МКПП`,
`CVT→Вариатор`, `DSG`, `AMT→Робот`; `DT→Дизель`, `EV→Электро`, `PHEV→Гибрид`;
`3.0` → объём; `(306 л.с.)` → мощность) и агрегируется в диапазонные записи
таблицы `configurations` (min/max по группе КПП+топливо).

**Выбранная стратегия (P-04):** приоритет — API cars-base.ru (быстро, надёжно,
без уязвимости к антиботу); при его недоступности — автоматический переход на
Playwright-парсинг HTML auto.ru.

## Установка и запуск

Требования: **Python 3.11+** (Windows 10/11 x64 или Linux для разработки).

```bat
cd APrice
python -m venv .venv
.venv\Scripts\activate          :: Windows (Linux: source .venv/bin/activate)
pip install -r requirements.txt
playwright install chromium     :: браузер для HTML-фолбэка (опционален,
                                 :: если основной API доступен — не используется)
python -m builder.main
```

При первом запуске автоматически создаются `config/settings.json`,
`data/aprice.db` (со схемой v2) и каталог `logs/`. Если существует база старой
схемы v1, при открытии выполняется автоматическая миграция до v2
(`builder/migrations.py`) с обязательной резервной копией
`data/aprice.db.bak-v1` и записью `schema_version = 2` в `metadata`.

**Играет роль:** Chromium нужен Builder'у только если основной API
cars-base.ru окажется недоступен. Перед запуском HTML-фолбэка выполняется
предпроверка наличия браузера; при его отсутствии в GUI появляется дружелюбное
сообщение «Браузер Chromium для Playwright не установлен. Выполните:
`playwright install chromium`» — без трейсбека (задача №2, п. 1.1).

### Конфигурация (`config/settings.json`)

```json
{
  "builder": {
    "request_delay_sec": [1, 3],
    "cache_ttl_hours": 168,
    "source": "auto.ru",
    "limit_brands": 5,
    "cars_base_token": "test",
    "headless": true
  },
  "logging": {
    "level": "INFO",
    "max_file_size_mb": 10,
    "backup_count": 3
  }
}
```

| Ключ | Назначение |
|---|---|
| `builder.request_delay_sec` | Паузы между запросами (P-07) |
| `builder.cache_ttl_hours` | TTL JSON-кэша `data/cache/` (P-06) |
| `builder.limit_brands` | Лимит марок за прогон: `5` — валидация, `null` — полный обход (задача №2, п. 1.4). В GUI соответствует чекбокс **«Ограничить 5 марками (валидация)»** — состояние двусторонне синхронизировано с этим ключом |
| `builder.generations_per_model` | `true` (по умолчанию): поколения моделей, которых нет в общем ответе `/generations` (список мог быть усечён), запрашиваются по одной модели — `/generations?model_id=…`. Каждый такой запрос идёт с паузой 1–3 с, поэтому при усечённом списке полный сбор занимает часы; `false` — только общий список |
| `builder.cars_base_token` | Токен API cars-base.ru (по умолчанию публичный `"test"`; для промышленного объёма — постоянный ключ) |
| `builder.headless` | Режим Chromium для HTML-фолбэка: `false` — видимое окно |
| `logging.*` | Уровень, размер и число резервных файлов логов |

### Работа в окне Builder

* **«Обновить базу»** — парсинг каталога в фоновом потоке (`QThread`), GUI не
  блокируется; прогресс и сообщения парсера — в лог-панели, статус — дата
  последнего обновления и количество марок/моделей/поколений в БД.
* **Чекбокс «Ограничить 5 марками (валидация)»** — снятие включает полный обход
  всех доступных марок; выбор сохраняется в `settings.json`.
* **«Остановить»** — корректное прерывание парсинга (stop-event).
* **«Сохранить лог»** — выгрузка лог-панели в файл.
* **«Очистить кэш»** — удаляет все файлы `data/cache/` (в т. ч. устаревшие или пустые
  ответы прошлых запусков); следующий сбор запросит данные заново. Недоступна во время сбора.
  Пустые ответы общих списков (`/full`, `/generations`) в кэш больше не записываются.
* **Полный сбор:** при снятом чекбоксе (`limit_brands: null`) обрабатываются **все** марки
  каталога (раньше оставлялись лишь «популярные», около 30). В логе по окончании:
  `Обновление завершено. Марки: …, модели: …, поколения: …`; отдельной строкой —
  `API /generations: получено поколений: N` и `Поколения: из общего списка …, запросами по моделям …`.
  *Известное ограничение:* поведение реального API `/generations` (пагинация, поддержка
  `model_id`) проверить без сети не удалось; если API игнорирует `model_id`, запросы по
  моделям автоматически отключаются (предупреждение в логе), и берётся то, что отдал общий список.
* Повторный запуск не дублирует записи (UPSERT, P-09), а обновляет `updated_at`;
  неизжившие ответы берутся из кэша.

## Схема БД (`data/aprice.db`, версия 2)

Таблицы `manufacturers`, `models`, `generations`, `configurations`, `metadata`
(см. ТЗ, п. 3). Отличие схемы v2 от v1: в `configurations` добавлено
`UNIQUE (generation_id, transmission, fuel_type)` — бизнес-ключ конфигурации,
благодаря чему дедупликация выполняется честным
`INSERT ... ON CONFLICT ... DO UPDATE` вместо «SELECT перед INSERT».
Миграция существующих баз — `builder/migrations.py::migrate_to_v2`
(идемпотентна, дубликаты схлопываются `INSERT OR IGNORE`, копия — `.bak-v1`).

## Менеджер окон (W-01..W-06) — зафиксирующие решения

* Хранение геометрии: **`QSettings` в формате INI** — файл рядом с
  `.exe`/корнем проекта (W-04). Выбор вместо реестра: portable-совместимость,
  отсутствие UAC, переносимость между ОС при разработке.
* **Отдельный INI-файл на компонент** (задача №2, п. 2.1): параметр
  `WindowManager(settings_filename=...)`; Builder —
  `config/aprice_builder_settings.ini`, Server — `aprice_server_settings.ini`,
  Client — `aprice_client_settings.ini` (константы — в `common/constants.py`).
  Старый общий `aprice_settings.ini` автоматически мигрируется в файл Builder.
* W-01 — первое открытие строго в центр `availableGeometry()` экрана
  (учёт панели задач); W-02 — `pos()/size()` сохраняются в `closeEvent`
  **и** при сигнале `QApplication.aboutToQuit` (реестр всех зарегистрированных
  окон — задача №2, п. 1.5; переживает завершение через `QApplication.quit()`);
  W-03 — `WindowManager.center_error(dialog)` центрирует диалоги ошибок и
  никогда их не сохраняет; W-05 — при восстановлении проверяется пересечение
  с любым экраном, иначе — центрирование; W-06 — единый API
  `apply(window, window_id)` / `center_error(dialog)` для всех компонентов.

## SSL/прокси и парсер auto.ru (Server, 3.7)

Server читает секцию `server` из `config/settings.json`:

```json
"server": { "ignore_https_errors": true, "playwright_headless": true }
```

* `ignore_https_errors` (по умолчанию `true`) — Playwright игнорирует ошибки
  сертификатов. Нужно в сетях с MITM-прокси и self-signed сертификатом, иначе
  `net::ERR_CERT_AUTHORITY_INVALID`. Если MITM нет — поставьте `false`.
* `playwright_headless` — `false` покажет окно Chromium (удобно для отладки CAPTCHA).
* Браузер: `playwright install chromium` (в тестах не нужен — они на моках).
* auto.ru без прогретых cookie часто отдаёт CAPTCHA (Yandex SmartCaptcha) —
  это ожидаемое поведение: парсер сообщает о ней (`CaptchaDetectedError`), сервер
  показывает диалог; CAPTCHA не обходится. Разбор выдачи auto.ru реализован по
  публичным примерам и **не проверен в сети** — см. docstring `server/parsers/autoru.py`.
* Площадки: активны `auto.ru`, `drom.ru`, `avito.ru`. `bibika.ru` и `sberauto.com`
  отключены решением Заказчика: в запросе они принимаются, но по ним возвращается
  ошибка `unsupported`, остальные площадки собираются. Если `options.sites` не
  передан, берётся `server.default_sites` из `settings.json`.
* Все три парсера отбрасывают объявления с годом вне `[year_from, year_to]` на
  своей стороне, даже если сайт проигнорировал параметры года в URL.
* Опции заданий: `test_fast_mode` только сокращает паузы, а `use_stub_data` возвращает
  заглушку без сети (для автотестов). Реальный смоук: без `use_stub_data`.

## APrice-Client (задача №4, 4.1 — скелет, 4.2 — статистика и история, 4.3 — графики и жизненный цикл, 4.4 — экспорт, настройки, обновление базы)

Запуск: `python -m client.main` (Server должен быть запущен: `python -m server.main`).

* Окно (4.6): одна форма «Параметры поиска» — марка и модель (из `data/aprice.db`),
  диапазоны годов и объёма, КПП и топливо — чекбоксы. Режима «Точный автомобиль» нет:
  точный год задаётся как «Год от» = «Год до». «Оценить» активна, когда выбраны марка и
  модель. Client всегда отправляет `mode: "range"`; Server по-прежнему принимает и
  `mode: "exact"`. Старые записи истории с `mode: "exact"` открываются как диапазон
  «год от = год до».
* Задание уходит на Server по IPC (`submit_task`), статус опрашивается раз в 2 с,
  «Остановить» шлёт `stop_task`. Если Server не запущен — сообщение «Сервер не запущен».
* После `completed` объявления читаются **напрямую из SQLite**
  (`data/aprice_server_state.db`, только чтение). В 4.1 выводятся количество и разбивка
  по площадкам.
* **Статистика (4.2)** — `client/stats.py` (без Qt, numpy): минимум, максимум, среднее,
  медиана и усечённое среднее (отбрасывается по 10 % с каждого конца). Числа в таблице —
  `5 640 000 ₽`. Меньше 10 цен — красное предупреждение под таблицей; цены `<= 0`/не числа
  исключаются и упоминаются в предупреждении.
* **История (4.2)** — `client/history.py`: последние 10 оценок в
  `data/aprice_client_history.json` (только `spec` и показатели, не объявления; файл в
  `.gitignore`). Выпадающий список «История запросов» восстанавливает форму и показывает
  сохранённые показатели **без** нового сбора. Оценка без цен в историю не попадает;
  повреждённый файл читается как пустая история.
* **Графики (4.3)** — вкладка «Графики»: гистограмма (20 бинов) и box plot
  (`client/charts.py`, matplotlib, холст `FigureCanvasQTAgg`). Рисуются по ценам
  последнего сбора; для записи из истории цены не хранятся, график пуст.
* **VPN-плашка (4.3)** — жёлтая строка «отключите VPN» вверху окна; скрывается по ✕ и
  через 10 с. Отключается настройкой `client.show_vpn_warning: false` в `settings.json`.
* **Жизненный цикл (4.3)** — Client при старте открывает с Server долгоживущий «сеанс»
  (`get_active_task` с `session=true`). Закрыли Client, а заданий нет — Server завершается;
  есть активное задание — Server продолжает работу. Client, запущенный снова, **подхватывает**
  выполняющееся задание (форма восстанавливается, опрос продолжается). Если Server запущен
  позже Client, сеанс открывается при первой отправке задания.
* **Экспорт (4.4)** — кнопка «Экспорт» на вкладке «Результат»: сырые объявления в `.csv`
  (разделитель `;`, UTF-8 с BOM — открывается в Excel) или `.xlsx` (pandas + openpyxl).
  Столбцы: `Площадка, Марка, Модель, Год, Цена, Пробег, Ссылка`. Доступна после сбора;
  для записи из истории объявления не хранятся, экспортировать нечего.
* **Настройки (4.4)** — кнопка «Настройки», секция `client` в `config/settings.json`:
  `max_pages_per_site` (2), `max_ads_per_site` (50) — уходят Server в `options` при каждом
  задании; `db_update_url`, `db_date_url` (по умолчанию — ссылки Яндекс.Диска), `db_max_age_days` (180 — полгода) —
  зеркало справочника, ссылка на `date.txt` и порог «база устарела». Положение окна запоминает `WindowManager` (`settings_dialog`).
* **Обновление базы из зеркала (4.4)** — «Обновить базу из зеркала» в настройках скачивает
  `aprice.db` по `db_update_url` в фоновом потоке. Подходит прямая ссылка или публичная
  ссылка Яндекс.Диска. Файл проверяется (сигнатура SQLite, `PRAGMA integrity_check`, таблицы
  и непустой список марок), затем прежняя база копируется в `data/aprice.db.bak`, а новая
  подменяется атомарно. При любой ошибке рабочая база не меняется. Объявления не затрагиваются.
* **Умное обновление (4.5)** — рядом с `aprice.db` на зеркале лежит `date.txt` с датой публикации
  (`DD.MM.YYYY`, `DD.MM.YYYY HH:MM:SS` или ISO 8601, например `17.11.2026` /
  `2026-11-17T12:00:00`; нераспознанная дата → предупреждение в логе и «обновление не
  требуется»). По кнопке «Обновить базу из зеркала» Client
  сначала скачивает этот крошечный файл (`db_date_url`; публичную ссылку Яндекс.Диска
  разрешает через `cloud-api.yandex.net`) и сравнивает дату с локальной базой: берётся
  `metadata.last_update`, а если его нет — время изменения файла. Если удалённая дата
  **строго новее** — база скачивается (а её время изменения выставляется равным дате из
  `date.txt`, поэтому сравнение остаётся верным и для скопированной вручную базы). Если дата
  равна или старше — показывается «Обновления не требуются», трафик на 5 МБ не тратится.
  Дата без часового пояса считается местным временем; со смещением (`+03:00`, `Z`) — точным
  моментом. Ошибка получения даты (нет сети, в файле не дата) показывается сообщением, базу
  не трогает. Пустой `db_date_url` отключает проверку (база скачивается всегда, как в 4.4).
  Проверка и скачивание идут в одном фоновом потоке, окно не зависает.
* Структура: `client/form.py` (состояние формы и `spec`, без Qt), `client/repository.py`
  (чтение баз), `client/stats.py`, `client/history.py` (без Qt),
  `client/controller.py` (IPC, опрос), `client/gui.py` (окно),
  `client/main.py` (точка входа).

## Состав дистрибутива

* **`APrice-Client.exe` + `APrice-Server.exe`** — основные программы для оценки стоимости
  (Server собирает объявления и живёт в трее, Client — окно оценки).
* **`APrice-Builder.exe`** — опциональная утилита для самостоятельного обновления
  справочников (для продвинутых пользователей). Основной способ получить базу — кнопка
  «Обновить базу из зеркала» в настройках Client (база качается с Яндекс.Диска, и только
  если на диске она новее локальной).

Компоненты независимы: `client` и `server` ничего не импортируют из пакета `builder`
(это проверяется тестом), поэтому Builder можно вообще не распространять.
По умолчанию база считается устаревшей через **180 дней** (`db_max_age_days`; для рынка
б/у автомобилей справочник марок и моделей меняется медленно).

Во всех окнах внизу — серый футер «АвтоПрайс 1.0 {Client|Server|Builder}. Copyright (c)
CoScore, 2026». По клику на него проверяется сайт <https://coscore.ru> (в фоновом
потоке, таймаут 2 с; сначала `HEAD`, при 403/405/501 — `GET` без загрузки тела) и, если он
отвечает `200 OK`, открывается в браузере; иначе ничего не происходит.

## Сборка и развёртывание (этап 5)

Распространяется **одна папка `dist/`** (PyInstaller, режим `--onedir`, 5.6) с тремя
`.exe` и **общим** каталогом библиотек `_internal`:

```
dist/
  APrice-Client.exe
  APrice-Server.exe
  APrice-Builder.exe
  _internal/        (Qt, Python и пр. — один раз на все три программы)
  config/ logs/ data/ browser/   (создаются при работе, общие для всех трёх)
  README.md  requirements.txt
```

Python на машине пользователя не нужен. Общие `config\`, `logs\`, `data\`, `browser\`
лежат рядом с `.exe`, поэтому Client и Server используют одни и те же настройки и один
Chromium.

### Для разработчика: как собрать

Сборка выполняется **на Windows 10/11 x64** (PyInstaller не кросс-компилирует).

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt pyinstaller
python build.py
```

`build.py` очищает `dist/` и `build/`, запускает PyInstaller для единой спецификации
`build_scripts/aprice.spec` (`--clean --noconfirm`; три `Analysis` и три `EXE` в одном
`COLLECT` — штатный приём «несколько exe в одной папке»), переносит `dist/APrice/*` в
`dist/`, копирует `README.md` и `requirements.txt` и выводит «Сборка завершена. Файлы в
dist/». У каждого компонента остались свои hiddenimports/excludes, поэтому состав
`_internal` — объединение трёх наборов (общие DLL Qt лежат один раз).

**Запасной вариант.** Если единая сборка на вашей машине не получилась (конфликт
библиотек и т.п.), выполните `python build.py --separate`: прежняя раскладка
`dist/{Builder,Server,Client}` из `builder.spec`, `server.spec`, `client.spec` (у каждого
свой `_internal`). Автозапуск Server из Client (см. ниже) находит `APrice-Server.exe` и в
этой раскладке (`..\Server`).

* `builder.spec` вшивает в Builder `data/aprice.db`, если он лежит в корне проекта; если
  файла нет, сборка **не падает** (выводится предупреждение, Builder соберётся без вшитой
  базы и создаст пустую схему). Client и Server базу не вшивают вообще.
* Каждый `.spec` включает только свои зависимости (остальное — в `excludes`):
  Builder — PyQt6 + sqlite3 (без matplotlib/playwright/pandas/numpy/openpyxl);
  Server — PyQt6 + playwright (`collect_all('playwright')`, нужен драйвер для
  установки Chromium); Client — PyQt6 + matplotlib (`collect_all('matplotlib')`) +
  pandas/numpy/openpyxl/requests (без playwright). Пакет PyQt6 целиком не
  собирается: берутся только используемые модули Qt. При `ModuleNotFoundError` в
  собранном приложении добавьте модуль в `hiddenimports` нужного `.spec`
  (и уберите из `excludes`, если он там указан).
* В собранном Builder HTML-фолбэк через Playwright недоступен (основной источник —
  API cars-base.ru).
* Chromium в сборку **не** входит (иначе +200 МБ): Server скачивает его сам.

### Для пользователя: как запускать

0. Достаточно запустить **`APrice-Client.exe`**: если Server ещё не работает, Client сам
   запускает `APrice-Server.exe` из своей папки (5.6) и ждёт, пока тот начнёт принимать
   подключения (до 30 с; при первом запуске может уйти дольше из-за установки Chromium —
   тогда сеанс откроется при первой оценке). При закрытии Client Server завершается сам,
   если нет активного задания; при активном задании остаётся работать (его подхватит
   следующий запуск Client). Отключить автозапуск: `client.autostart_server = false` в
   `config/settings.json`.
1. Либо запустите **`APrice-Server.exe`** вручную — окно не появится, приложение свернётся в
   трей. Браузер Chromium ищется в папке `browser\` **рядом с `.exe`** (см. ниже); если
   его там нет, при первом запуске Server скачает его автоматически (окно «Идёт
   установка браузера», нужен интернет, ~150 МБ, один раз).
2. Запустите **`APrice-Client.exe`** — окно оценки стоимости. При первом запуске, если
   рядом нет `data\aprice.db`, Client **сам скачивает справочник** с зеркала
   (`db_update_url`) под окном «Загрузка справочника... Это займет около минуты»
   (нужен интернет). Если скачать не удалось (нет сети, битая ссылка), показывается
   ошибка и программа закрывается — без справочника марки и модели недоступны;
   проверьте подключение и запустите её снова.
3. **`APrice-Builder.exe`** нужен только для обновления справочников
   (марки/модели/поколения). При первом запуске он копирует вшитую
   `aprice.db` в `data\` рядом с собой. Чтобы Client увидел собранную вами базу,
   скопируйте её в `data\` рядом с `APrice-Client.exe`; обычное обновление — кнопка
   «Настройки → Обновить базу из зеркала» в Client.

Папки `config\`, `logs\` и `data\` создаются **рядом с `.exe`** (а не во временной
папке PyInstaller); в единой сборке это общая `dist\`.

### Chromium: portable-режим (5.2)

Server задаёт `PLAYWRIGHT_BROWSERS_PATH = <папка .exe>\browser`, поэтому браузер хранится
**рядом с программой**, а не в `AppData\Local\ms-playwright`: папку `dist\Server`
можно переносить целиком вместе с `browser\`. В режиме разработки это `browser/` в
корне проекта (он в `.gitignore`).

Если вы используете собранную версию (`APrice-Server.exe`), браузер Chromium должен лежать
в папке `browser` рядом с `.exe`. При первом запуске сервер попытается скачать его
автоматически. Если скачивание не удалось (например, из-за антивируса), скачайте архив
Chromium вручную и распакуйте в `browser/chromium-[версия]`. Проще всего скопировать
готовое содержимое `%LOCALAPPDATA%\ms-playwright` с компьютера, где выполнена команда
`playwright install chromium` (там же лежат `chromium_headless_shell-*` и `ffmpeg-*`,
которые нужны для headless-режима), в `browser\` рядом с `APrice-Server.exe`.

Если браузер не найден, Server покажет сообщение «Chromium не найден по пути [путь].
Установите его или положите в папку browser/ рядом с программой» (в нём указан точный
путь, где ожидается `chrome.exe`) и продолжит работу; сбор объявлений при этом недоступен.

### Ускорение загрузки Chromium (5.6)

При автоматической установке Server качает Chromium **через зеркало**
`https://npmmirror.com/mirrors/playwright` (в окружение процесса установки передаётся
`PLAYWRIGHT_DOWNLOAD_HOST`). Если зеркало недоступно или установка с него не удалась, Server
**автоматически повторяет** установку с официального CDN Playwright. Управление
(переменные окружения Windows, задаются до запуска `APrice-Server.exe`):

| Переменная | Значение | Эффект |
|---|---|---|
| `APRICE_CHROMIUM_MIRROR` | не задана | зеркало npmmirror, при сбое — официальный CDN |
| `APRICE_CHROMIUM_MIRROR` | `off` (также `0`, `false`, `official`, `cdn`) | только официальный CDN, без зеркала |
| `APRICE_CHROMIUM_MIRROR` | `https://my.mirror/playwright` | своё зеркало (с тем же откатом на CDN) |
| `PLAYWRIGHT_DOWNLOAD_HOST` или `PLAYWRIGHT_CHROMIUM_DOWNLOAD_HOST` | любой адрес | выбор пользователя приоритетнее: APrice ничего не подставляет и Playwright использует ваш адрес |

Пример (cmd): `set APRICE_CHROMIUM_MIRROR=off` и затем `APrice-Server.exe`.

### Системные требования

Windows 10/11 x64, 4 ГБ ОЗУ, ~1 ГБ свободного места (с учётом Chromium),
доступ в интернет для сбора объявлений.

### Автозапуск Server (Планировщик задач Windows)

1. Win+R → `taskschd.msc` → **Создать задачу…** (не «простую»).
2. Вкладка **Общие**: имя `APrice-Server`; «Выполнять только для пользователя,
   вошедшего в систему».
3. Вкладка **Триггеры** → **Создать** → «Начать задачу»: **При входе в систему**
   (укажите нужного пользователя).
4. Вкладка **Действия** → **Создать** → «Запуск программы»: путь к
   `...\Server\APrice-Server.exe`; в поле «Рабочая папка» — `...\Server`.
5. Вкладка **Условия**: снимите «Запускать только при питании от сети»
   (для ноутбуков). **ОК**.

Server — GUI-приложение для трея, поэтому задача должна выполняться в сеансе
пользователя (не «независимо от входа пользователя в систему»).

## Допущения и открытые вопросы

1. **auto.ru без «прогревания» стабильно отдаёт CAPTCHA** — подтверждено
   экспериментально. Для боевого HTML-парсинга может потребоваться headful-
   режим (`builder.headless: false`) и повторные попытки; сейчас фолбэк честно
   сообщает о блокировке (P-08).
2. **`?token=test` cars-base.ru** — публичный тестовый ключ, заявленный самим
   сервисом. Для промышленного объёма (все 428 марок) рекомендуется купить
   постоянный токен и положить его в `settings.json` (`builder.cars_base_token`).
3. Поколения в cars-base.ru не содержат слова «рестайлинг» — имена нормализуются
   как `«IV (2018–2021)»`; решение ТЗ-разработчика — приемлемо для v1,
   обогащение рестайлингами — отдельная задача.
4. Полный обход всех марок включается снятием чекбокса в GUI (или
   `builder.limit_brands: null` в конфиге); по умолчанию — 5 марок для
   валидации, чтобы Заказчик включал полный обход явно.
5. Парсинг выполняется синхронным HTTP (stdlib) для API; Playwright подключается
   лениво — только в HTML-ветке, с предпроверкой установленного браузера.
